# WsConnection - MemoryPack Migration Guide

## Overview

The `WsConnection.ts` has been migrated from a custom binary serialization format to use **MemoryPack** auto-generated TypeScript classes. This provides:

- ✅ **Type safety** - Full TypeScript types for all messages
- ✅ **Auto-sync** - TypeScript definitions generated from C# automatically
- ✅ **No manual serialization** - MemoryPack handles all binary encoding/decoding
- ✅ **Version tolerance** - Built-in support for schema evolution
- ✅ **Better performance** - Optimized binary format

## File Structure

```
WsCore.Client/src/network/
├── WsConnection.ts           # New MemoryPack-based connection (USE THIS)
├── WsConnection_old.ts       # Old custom buffer implementation (deprecated)
├── WsConnectionExample.ts    # Usage examples
└── protocol/                 # Auto-generated by MemoryPack
    ├── MemoryPackReader.ts   # Binary reader
    ├── MemoryPackWriter.ts   # Binary writer
    ├── InitPlayerEvent.ts
    ├── PlayerJoinedEvent.ts
    ├── UpdatePlayerStateRequest.ts
    └── ... (all other messages)
```

## Quick Start

### 1. Basic Connection

```typescript
import WsConnection from './network/WsConnection.js';

const connection = new WsConnection();
connection.connect(); // Auto-detects WebSocket URL

// Or specify custom URL:
connection.connect('ws://localhost:5000/ws');
```

### 2. Handle Server Events

Override the event handler methods:

```typescript
class GameConnection extends WsConnection {
  override onInitPlayerEvent(msg: InitPlayerEvent): void {
    this.clientId = msg.clientId;
    console.log('Connected as player:', msg.clientId);
  }

  override onPlayerJoinedEvent(msg: PlayerJoinedEvent): void {
    console.log('Player joined:', msg.playerStateData);
    // Add player sprite to game
  }

  override onGameTickUpdateEvent(msg: GameTickUpdateEvent): void {
    // Update game state every server tick
    msg.movementStates?.forEach(state => {
      if (state) {
        this.updatePlayer(state.playerId, state);
      }
    });
  }
}
```

### 3. Send Requests to Server

```typescript
// Send player movement
connection.sendUpdatePlayerStateRequest(mouseX, mouseY, controlsState);

// Shoot weapon
connection.sendPlayerShootingRequest(weaponId);

// Chat message
connection.sendChatMessageRequest('Hello world!');

// Respawn
connection.sendPlayerRespawnRequest();

// Change equipment
connection.sendUpdatePlayerSlotsRequest(bodyId, gunId, armorId);
```

## Migration from Old Code

### Before (Custom Buffer)

```typescript
// Old way - manual serialization
this.writeBuff
  .newMessage()
  .pushUInt8(ClientMessageType.UpdatePlayerStateRequest)
  .pushFloat(AimX)
  .pushFloat(AimY)
  .pushInt32(ControlsState)
  .send(this.ws);
```

### After (MemoryPack)

```typescript
// New way - type-safe objects
connection.sendUpdatePlayerStateRequest(aimX, aimY, controlsState);
```

### Deserialization Changes

**Before:**

```typescript
const playerJoinedEvent = new PlayerJoinedEvent();
playerJoinedEvent.PlayerStateData = this.readPlayerStateData(buff);
this.onPlayerJoinedEvent(playerJoinedEvent);
```

**After:**

```typescript
// Automatic deserialization from MemoryPackReader
this.onPlayerJoinedEvent(PlayerJoinedEvent.deserializeCore(reader)!);
```

### Server Events (Server → Client)

```typescript
InitPlayerEvent = 1
PlayerJoinedEvent = 2
PlayerLeftEvent = 3
PlayerRespawnEvent = 4
SetPlayerHpEvent = 5
...
```

### Client Requests (Client → Server)

```typescript
UpdatePlayerStateRequest = 101
PlayerShootingRequest = 103
PlayerRespawnRequest = 105
ChatMessageRequest = 200
...
```

## Adding New Messages

When you add a new message type on the server:

1. **Add C# class** with `[MemoryPackable]` and `[GenerateTypeScript]`:

   ```csharp
   [GenerateTypeScript]
   [MemoryPackable]
   public partial class NewMessageRequest : IClientRequest
   {
       public int SomeValue { get; set; }
   }
   ```

2. **Rebuild server** - TypeScript files auto-generate in `WsCore.Client/src/network/protocol/`

3. **Import in WsConnection.ts**:

   ```typescript
   import { NewMessageRequest } from './protocol/NewMessageRequest.js';
   ```

4. **Add handler method**:
   ```typescript
   sendNewMessageRequest(someValue: number): void {
       const request = new NewMessageRequest();
       request.someValue = someValue;
       const data = NewMessageRequest.serialize(request);
       this.sendMessage(ClientMessageType.NewMessageRequest, data);
   }
   ```

## Property Name Mapping

MemoryPack converts C# PascalCase to TypeScript camelCase:

```csharp
// C# (server)
public int PlayerId { get; set; }
public float AimX { get; set; }
```

```typescript
// TypeScript (client)
playerId: number;
aimX: number;
```

## Performance Notes

- Messages are serialized to `Uint8Array` (binary format)
- Very compact binary encoding (smaller than JSON)
- Zero-copy deserialization where possible
- No reflection or dynamic code generation at runtime

## Common Issues

### Issue: "Property does not exist on type"

**Cause:** Property name doesn't match generated TypeScript  
**Fix:** Check the generated `.ts` file in `protocol/` folder for correct property name (camelCase)

### Issue: Messages not deserializing

**Cause:** Message type ID mismatch between client and server  
**Fix:** Ensure `ServerEventType` and `ClientMessageType` enums match server-side type IDs

### Issue: WebSocket not connecting

**Cause:** URL configuration  
**Fix:** Check browser console for connection errors, verify server is running
