# WsConnection - MemoryPack Guide

## Overview

The `WsConnection.ts` has been migrated from a custom binary serialization format to use **MemoryPack** auto-generated TypeScript classes. This provides:

- ✅ **Type safety** - Full TypeScript types for all messages
- ✅ **Auto-sync** - TypeScript definitions generated from C# automatically
- ✅ **No manual serialization** - MemoryPack handles all binary encoding/decoding
- ✅ **Version tolerance** - Built-in support for schema evolution
- ✅ **Better performance** - Optimized binary format

## File Structure

```
WsCore.Client/src/network/
├── WsConnection.ts           # Transport: socket, reconnect/backoff, watchdog, dispatch table
├── WsClient.ts               # Session state: rooms, joins, players, typed events
└── protocol/                 # Auto-generated by MemoryPack
    ├── MemoryPackReader.ts   # Binary reader
    ├── MemoryPackWriter.ts   # Binary writer
    ├── InitPlayerEvent.ts
    ├── PlayerJoinedEvent.ts
    ├── UpdatePlayerStateRequest.ts
    └── ... (all other messages)
```

## Quick Start

### 1. Basic Connection

```typescript
import WsConnection from './network/WsConnection.js';

const connection = new WsConnection();
connection.connect(); // Auto-detects WebSocket URL

// Or specify custom URL:
connection.connect('ws://localhost:5000/ws');
```

### 2. Handle Server Events

Override the event handler methods:

```typescript
class GameConnection extends WsConnection {
  override onInitPlayerEvent(msg: InitPlayerEvent): void {
    this.clientId = msg.clientId;
    console.log('Connected as player:', msg.clientId);
  }

  override onPlayerJoinedEvent(msg: PlayerJoinedEvent): void {
    console.log('Player joined:', msg.playerStateData);
    // Add player sprite to game
  }

  override onGameTickUpdateEvent(msg: GameTickUpdateEvent): void {
    // Every tick snapshot (~15 Hz). Deltas: only avatars that changed recently are
    // included (all of them in the periodic full snapshot); absent = unchanged.
    msg.movementStates?.forEach(state => {
      if (state) {
        this.updatePlayer(state.playerId, state);
      }
    });
  }
}
```

### 3. Send Requests to Server

```typescript
// Send player movement
connection.sendUpdatePlayerStateRequest(mouseX, mouseY, controlsState);

// Shoot weapon
connection.sendPlayerShootingRequest(weaponId);

// Chat message
connection.sendChatMessageRequest('Hello world!');

// Respawn
connection.sendPlayerRespawnRequest();

// Change equipment
connection.sendUpdatePlayerSlotsRequest(bodyId, gunId, armorId);
```

## Message Type IDs

The ids live in the `ServerEventType` / `ClientMessageType` enums at the top of
`WsConnection.ts` and must equal the server's `static byte TypeId` values;
`WsConnection.test.ts` parses the C# sources and fails on any drift. A few examples:

```typescript
GameStateUpdateEvent = 0;
GameTickUpdateEvent = 1;
HeartbeatEvent = 7; // liveness only, feeds the watchdog
RoomListEvent = 250;
JoinRoomResultEvent = 252;
InitPlayerEvent = 255;
```

## Rooms, joins and players (session model)

- **Rooms come from the server.** `WsClient` requests the room list on every session
  init (`InitPlayerEvent`) and replaces its `RoomManager` contents with each
  `RoomListEvent` (`roomList` event). Nothing about rooms is hard-coded on the client.
- **Joins are server-confirmed.** `joinRoom(id)` only sends `JoinRoomRequest`; the
  server answers with `JoinRoomResultEvent` → `roomJoined(id)` (membership + spatial
  mode updated) or `roomJoinFailed(id, error)` (nothing changed). The server's automatic
  lobby join on connect is confirmed the same way and becomes `homeRoomId`.
- **A connection is not a player.** `players` is empty outside a spatial room. Entering
  the game: `JoinRoomResultEvent` then `GameStateUpdateEvent` (every player incl. our
  own → `playerCreate`, `myPlayer`). Leaving it: all players are removed (`playerRemove`
  each) when the lobby join is confirmed.

## Connection watchdog

The server sends `HeartbeatEvent` to every connection every 5 s. If nothing at all
arrives for `WsConnection.WATCHDOG_TIMEOUT_MS` (15 s) while the status is `open`, the
socket is presumed dead, detached and closed, and the normal reconnect/backoff path runs
(status `reconnecting` → banner). A check that finds its own timer was suspended (frozen
tab, sleep) — or the tab becoming visible — starts a new grace window instead of
reconnecting.

## Adding New Messages

When you add a new message type on the server:

1. **Add C# class** with `[MemoryPackable]` and `[GenerateTypeScript]`:

   ```csharp
   [GenerateTypeScript]
   [MemoryPackable]
   public partial class NewMessageRequest : IClientRequest
   {
       public int SomeValue { get; set; }
   }
   ```

2. **Regenerate the TS types** (see the root `CLAUDE.md`: uncomment the
   `MemoryPackGenerator_TypeScriptOutputDirectory` block, build, re-comment).

3. **Add the TypeId to the client enum** in `WsConnection.ts` — `ClientMessageType`
   for a request, `ServerEventType` for an event, same name and id as the server.
   `WsConnection.test.ts` parses the C# sources and fails on any mismatch, either way.

4. **Request:** add a send method:

   ```typescript
   sendNewMessageRequest(someValue: number): void {
       const request = new NewMessageRequest();
       request.someValue = someValue;
       const data = NewMessageRequest.serialize(request);
       this.sendMessage(ClientMessageType.NewMessageRequest, data);
   }
   ```

   **Event:** add an `onNewEvent(msg)` hook to `ServerEventHandlers` + a no-op in
   `WsConnection`, and one row in `SERVER_EVENT_ROUTES`:

   ```typescript
   [ServerEventType.NewEvent]: route(NewEvent, (h, m) => h.onNewEvent(m)),
   ```

   The table is typed `{ [K in ServerEventType]: ServerEventRoute }`, so a missing row
   is a compile error. Override the hook in `WsClient`; if it should reach app code,
   add an entry to `ClientEvents` (`ClientEvents.ts`) and `emitter.emit()` it —
   `on()`/`emit()` are typed from that map.

## Property Name Mapping

MemoryPack converts C# PascalCase to TypeScript camelCase:

```csharp
// C# (server)
public int PlayerId { get; set; }
public float AimX { get; set; }
```

```typescript
// TypeScript (client)
playerId: number;
aimX: number;
```

## Performance Notes

- Messages are serialized to `Uint8Array` (binary format)
- Very compact binary encoding (smaller than JSON)
- Zero-copy deserialization where possible
- No reflection or dynamic code generation at runtime

    console.log("Received bytes:", Array.from(bytes).map(b => b.toString(16).padStart(2, '0')).join(' '));

    // ... rest of processing

```typescript

    console.log("PlayerJoinedEvent:", JSON.stringify(msg, null, 2));
}
```

## Common Issues

### Issue: "Property does not exist on type"

**Cause:** Property name doesn't match generated TypeScript  
**Fix:** Check the generated `.ts` file in `protocol/` folder for correct property name (camelCase)

### Issue: Messages not deserializing

**Cause:** Message type ID mismatch between client and server  
**Fix:** Run `npm run test` — `WsConnection.test.ts` names every enum entry that drifted from the server's TypeIds

### Issue: WebSocket not connecting

**Cause:** URL configuration  
**Fix:** Check browser console for connection errors, verify server is running
