# ASCII-арт и каомодзи в чате — план

Дата: 2026-11-16. Статус: реализован 2026-11-24 (арт — свой набор, 71 шт., `tools/ascii-art/art.txt`; схема БД v10 вместо ALTER-по-месту: миграция в `MigrateUsers`).

Цель: каталог ASCII-арта в чате (вместо стикеров и гифок, которые возможны позже) и каталог
ASCII-эмодзи (каомодзи).

## Ключевое решение

- **Каомодзи — обычный текст.** Вставляются в поле ввода, уходят как обычное сообщение.
  Протокол, сервер и база не меняются.
- **ASCII-арт — по ссылке, как стикер.** Сообщение несёт только `ArtId` (slug вроде `cat-03`),
  сам каталог лежит в клиенте.

Почему не многострочным текстом: `InputSanitizer.Clean` вырезает `\n` как управляющий символ,
`MaxChatLength` = 256, поле ввода в лобби однострочное. Ослабить всё это — значит разрешить
любому клиенту слать произвольные «стены» текста, а каждый арт (до ~2 КБ) класть в базу и в
окно истории в памяти (`ChatHistoryCacheSize` сообщений на комнату).

Следствия:

- Сервер не знает каталог: проверяет только формат id (`[a-z0-9-]{1,40}`). Неизвестный id
  клиент рисует как «арт недоступен». Обновление каталога не требует правок сервера.
- Тот же механизм позже подойдёт для стикеров и гифок.
- **id нельзя удалять и переиспользовать** — иначе старые сообщения в истории сломаются.
  Убранный из пикера арт остаётся в каталоге со скрытым флагом.

Вне рамок: свой арт пользователя (картинка → ASCII, FIGlet). Для него понадобится отдельный
тип сообщения с телом; текущая схема этому не мешает.

## Этап 1. Каомодзи (только клиент)

- `WsCore.Client/src/lobby/kaomoji.ts`: 200–300 штук по категориям (радость, грусть, злость,
  удивление, действия, животные и т. п.).
- Кнопка в композере (`.lobby-input-container` в `LobbyUI.ts`) открывает поповер; клик
  вставляет каомодзи в поле ввода по позиции курсора, поповер остаётся открытым.
- «Недавние» — в `localStorage` (доступ в try/catch).
- Поповер закрывается по Esc и клику снаружи; при уходе в игру и обратно не размножается
  (проверка утечек из процедуры smoke-теста).

## Этап 2. Контент арт-каталога

- Скрипт импорта вне бандла (`scripts/` или `tools/`): нормализует сырьё (обрезка пустых
  строк и общего левого отступа, замена табов), фильтрует, пишет
  `WsCore.Client/src/lobby/asciiArt.json`. Сырьё не коммитится, результат — коммитится.
- Формат записи: `id`, `title`, `tags`, `category`, `cols`, `rows`, `lines`, опционально
  `hidden`.
- Фильтр v1:
  - только печатный ASCII (U+0020–007E);
  - не шире 48 колонок, не выше 24 строк;
  - подписи авторов (инициалы в арте) сохраняются.
- Объём: 100–150 артов, ~20 КБ в gzip. Каталог **бандлится статически**: высота сообщения
  (`rows`) должна быть известна в момент рендера, иначе ломается коррекция скролла при
  подгрузке старых страниц истории. Пересмотреть, когда каталог вырастет.
- Источники: ручной отбор. Кандидаты из обсуждения (не проверены — существование и лицензии
  проверить перед импортом): `asweigart/asciiartjsondb`, `Leivmox/ASCII-ART`, asciiart.eu,
  emojicombos.com, textart.sh; для каомодзи — npm-пакеты `kaomoji` / `emoticon`. У
  классических архивов лицензии неясные (авторские работы), поэтому для публичного продакшена
  — ручной отбор, а не импорт архива целиком.

## Этап 3. Протокол, сервер, хранилище

Делать после того, как закоммичены правки под аккаунты в `SqliteChatStorage.cs` /
`IChatStorage.cs`.

- `ArtId` (string, пусто = обычное сообщение) в `ChatMessageRequest`, `ChatMessageEvent` и в
  элементе истории (`ChatHistoryEvent`).
- `ChatMessageRequestHandler`: если `ArtId` задан — валидация формата, текст игнорируется;
  невалидный id — сообщение отбрасывается. В лог — только факт и длина, не содержимое.
- Кулдаун: отдельная опция `ChatArtCooldownSeconds` в `GameServerOptions` (по умолчанию 2 с),
  чтобы экран не заливали картинками.
- База: колонка `art_id TEXT NOT NULL DEFAULT ''` в `messages` через `ALTER TABLE ADD COLUMN`
  (идемпотентная миграция для существующих баз); чтение/запись в `SqliteChatStorage`,
  `StorageSnapshot`, `ChatHistoryService`.
- Перегенерировать TS-типы (раскомментировать блок `MemoryPackGenerator_TypeScriptOutputDirectory`
  в `WsServer.csproj`, собрать, закомментировать обратно, `npm run format`).
- Закрепить байты в wire-тестах с обеих сторон (`ProtocolWireFormatTests`, `protocol.test.ts`).

## Этап 4. Рендер и пикер арта

- `ChatLog` / `WsClient` / `LobbyState`: `artId` проходит через кеш чата до `LobbyMessage`.
- `LobbyUI.buildMessage`: арт рисуется как `<pre class="lobby-message-art">`:
  - `white-space: pre`, системный моноширинный стек, `line-height` ~1.15;
  - `--cols` выставляется на элементе; на узком экране шрифт сжимается без JS:
    `font-size: min(13px, calc(100cqw / (var(--cols) * 0.62)))` (контейнер — тело сообщения
    с `container-type: inline-size`);
  - неизвестный id — заглушка «арт недоступен» фиксированной высоты.
- Вторая вкладка поповера из этапа 1: сетка уменьшенных превью, категории, поиск по `title` и
  `tags`, «недавние». Клик отправляет арт сразу.
- Фильтр сообщений (`matchesMessageFilter`) для арта матчит `title`, а не символы рисунка.
- Игровой оверлей `ChatUI` и TestClient в v1 показывают заглушку `[арт: <title>]`.

## Этап 5. Тесты

- Сервер (xUnit): `ArtId` в живом сообщении и в истории; переживает рестарт (SQLite);
  мусорный id отбрасывается; отдельный кулдаун; миграция базы без колонки `art_id`.
- Клиент (Vitest): `ChatLog` и `LobbyState` с арт-сообщениями; тест-валидатор каталога
  (уникальные id, формат id, лимиты `cols`/`rows`, совпадение `cols`/`rows` с `lines`,
  допустимый набор символов).
- Браузерный smoke — добавить в пункт 6 процедуры в `CLAUDE.md`: арт не переносится на ширине
  400px; подгрузка страницы истории с артами не сдвигает сообщение под вьюпортом; поповер не
  размножается за 10 циклов лобби → игра → лобби.
- Обновить `CLAUDE.md` (протокол чата, схема базы, новая опция).

## Позже: Braille-арт

Braille (U+2800–28FF) детальнее и компактнее, но в системных шрифтах ширина пустого `⠀` часто
не совпадает с остальными символами. Потребуется свой моноширинный шрифт (subset в woff2,
`@font-face`, грузится только при появлении глифов) и проверка покрытия диапазона. Формат
каталога и протокол не меняются: добавляется шрифт и снимается фильтр по символам.

## Открытые вопросы

- Арт с подписью или без. Заложено «без», как у стикера; с подписью усложняются хендлер и
  рендер.
