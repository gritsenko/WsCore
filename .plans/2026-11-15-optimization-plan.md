# План оптимизаций и улучшений WsCore

Дата: 2026-11-15. Основан на ревью архитектуры и кода после закрытия этапов 0–4 из
[2026-07-07-roadmap.md](2026-07-07-roadmap.md). Номера этапов здесь свои (A–F).

Принцип: сначала мелкие баги и гигиена, затем архитектурные изменения сервера, затем
изменения wire-формата (они затрагивают сервер и клиент одновременно), в конце — тулинг.

Проверка каждого этапа: `dotnet test` (WsServer.Tests), `WsServer.LoadTest`,
`npm run typecheck && npm run lint && npm run format:check && npm run test && npm run build`.
SDK .NET лежит в `~/.dotnet/dotnet` (в PATH его может не быть).

## Решения по апгрейдам

| Что | Решение |
|---|---|
| .NET 10 → 11 | Отложить. 11 — STS с тем же EOL (14.11.2028), что у 10 LTS; выгода (runtime async, JIT) для этого сервера маргинальна. Вернуться после 1–2 патчей. |
| Node 20 → 24 (Dockerfile, CI) | Сделать (этап A). Node 20 снят с поддержки. |
| Vite 6 → 8, Vitest 3 → 5 | Сделать (этап F), вместе с отказом от singlefile. |
| TypeScript 5.9 → 7 | Не трогать, пока typescript-eslint не поддержит TS 7. |
| three / prettier / MemoryPack | Минорные обновления, этап F. |

## Этап A — баги и гигиена (S)

Сервер:
- [ ] Тик-луп: try/catch на каждый тик, а не вокруг всего цикла (`GameServerBase.RunGameLoopAsync`); одно исключение сейчас убивает луп навсегда.
- [ ] `/health` отражает живость лупа (время последнего тика), а не всегда «healthy».
- [ ] `DateTime.Now` → монотонное время (`Stopwatch.GetTimestamp`) для dt.
- [ ] `new Random()` на вызов → `Random.Shared`.
- [ ] `Serialize<T>` берёт `T.TypeId` напрямую вместо поиска в словаре.
- [ ] Убрать приведение `(GameMessenger)Messenger` в `GameServer` (метод в интерфейс).
- [ ] Не сериализовать тик-снапшот, если spatial-получателей нет.
- [ ] Убрать аллокации на тик в `GameTickUpdateEvent.BuildTickSnapshot` без изменения wire-формата.

Клиент:
- [ ] WASD-обработчики игнорируют события, когда фокус в поле ввода (сейчас в чате нельзя набрать w/a/s/d).
- [ ] Клик-движение: слушать canvas, а не `document`; отличать клик от перетаскивания камеры.
- [ ] Анимация спрайтов и сглаживание камеры/позиций — через delta time, а не через счётчик кадров.
- [ ] `setPixelRatio(Math.min(devicePixelRatio, 2))`.
- [ ] Тени: убрать мёртвую настройку `castShadow`/shadow map (ничто не отбрасывает тень, `shadowMap.enabled` не включён).
- [ ] Мусор в конфигах: имя пакета `phaser-playable`, `jsx`/`allowJs` в tsconfig.

Инфраструктура:
- [ ] Node 24 в `Dockerfile` и `.github/workflows/ci.yml`.
- [ ] Dockerfile: сначала копировать csproj и делать restore (кэш слоя), убрать `useradd` в пользу встроенного пользователя `app`.

## Этап B — жизненный цикл и надёжность соединений (M)

- [ ] `GameServer` → hosted service (`BackgroundService` или `IHostedService`): явный старт/стоп, заменяет ручной хук `ApplicationStopping`. Луп стартует при запуске хоста, а не при первом подключении.
- [ ] Подключение и отключение клиента — через очередь команд на тик-поток. После этого `ConcurrentDictionary` и три `Lock` в `GameModel` заменить обычными коллекциями (где чтение с других потоков не требуется — проверить `/info`, тесты).
- [ ] WebSocket keep-alive: `KeepAliveInterval` + `KeepAliveTimeout` (~15 с) в `UseWebSockets`, значения в `GameServerOptions`.
- [ ] Клиент: сторожевой таймер «нет входящих сообщений N секунд → переподключение». Требует лёгкого серверного heartbeat-события для лобби (там трафика нет) — новый TypeId, регенерация TS.
- [ ] Раздельная очередь отправки: один слот «последний тик-снапшот» + очередь надёжных событий; при переполнении надёжной очереди клиент отключается. Нужен признак «ненадёжное» у события (маркер-интерфейс или параметр `Send`).

## Этап C — соединение ≠ игрок (M–L)

- [ ] Игрок в `GameModel` создаётся при входе в spatial-комнату и удаляется при выходе, а не при подключении. Идентичность клиента (id, имя) живёт отдельно от игрового аватара.
- [ ] `PlayerJoined`/`PlayerLeft`, слоты, выстрелы, карта — только участникам spatial-комнаты; чат — участникам комнаты отправителя (`BroadcastToRoom`).
- [ ] Клиент: `GameScene` получает состояние игроков при входе в `game`; лобби не создаёт `Player`-объекты.
- [ ] Комнаты — с сервера: `RoomListEvent` — единственный источник списка комнат, клиент не хардкодит `lobby/voice/game` и не «входит» оптимистично до подтверждения.
- [ ] Обновить тесты (xUnit, Vitest, интеграционный) и CLAUDE.md.

## Этап D — тик-снапшот (M)

- [ ] Сократить `MovementStateData`: убрать `BodyAngle`, `ControlsState` (если клиенту не нужны), `AnimationState` → `byte`.
- [ ] Слать только изменившихся игроков (dirty-флаг), с периодическим полным снапшотом.
- [ ] Симуляция 30 Гц, отправка 10–15 Гц (настройка в `GameServerOptions`).
- [ ] Клиент: буфер интерполяции между двумя снапшотами вместо `lerp` к последнему.
- [ ] Обновить зафиксированные байты в `protocol.test.ts`, прогнать LoadTest и сравнить трафик.

## Этап E — протокол на клиенте (S)

## Этап F — тулинг (S–M)

- [ ] Vite 8 + Vitest 5; убрать `vite-plugin-singlefile`, обычные хэшированные чанки.
- [ ] Ленивая загрузка игры: `import('./game/GameScene')` по кнопке Play — лобби без three.js.
- [ ] `Cache-Control` для хэшированной статики (ASP.NET static files / nginx).
- [ ] Минорные обновления three, prettier, typescript-eslint, MemoryPack.

## Порядок и параллелизм

Этап A делится на сервер и клиент — идут параллельно (файлы не пересекаются). B — в основном
сервер; параллельно с ним можно делать F на клиенте. C и D меняют протокол и обе стороны —
строго последовательно, по одному исполнителю на этап. E — после D.
